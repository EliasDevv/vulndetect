# Results

All reported numbers come from the files in this directory. Tables and
figures are regenerated from them with `make eval`, `make eval-val` and
`make tables` (see the top-level README).

## Structure

```
results/
├── experiments.csv        log of all official runs (one row per run)
├── metrics/               comparisons and diagnostics (the `.tex` tables are regenerated by `make eval` / `make tables`)
├── figures/               figures of chapter 7 (PDF)
├── predictions/           one folder per run: <experiment>/seed<N>/[<snapshot>/]
├── gan_val/               GAN loop outputs (strategy memories, rounds, snapshots) per seed
├── gan_val_phaseb_only/   loop of the Phase-B-only ablation
├── triple_agent_val/      Triple-Agent loop outputs per seed
├── training/              SFT training manifests (loss, runtime, config hash)
└── logs/gpu-server/       console logs of the GPU server runs and queue_status.tsv
```

Each run folder contains `manifest.json` (config, config hash, model revision,
prompt and parser version, decoding), `predictions.jsonl` (one line per
instance with raw model output and parsed label) and `metrics.json`.

## Validation, control and ablation runs (val split)

Folders ending in `_val` are the same configuration on the validation split.
The suffixes mean:

| Suffix / folder              | Meaning                                                               |
|------------------------------|-----------------------------------------------------------------------|
| `_dec06`                     | RAG with the Baseline decoding (temperature 0.6, 512 new tokens), which the final RAG configuration also uses; `rag_val_dec06` is therefore a second run of `rag_val` |
| `_nocontext`                 | RAG without retrieved context                                         |
| `_random`                    | RAG with random catalogue chunks as context                           |

The RAG control runs without `_dec06` (`rag_val_nocontext`, `rag_val_random`) use
the earlier RAG decoding (temperature 0.1, 384 new tokens), as stated in their configs.
| `baseline_val_date`          | Baseline with a different chat date in the system prompt              |
| `baseline_val_strict`        | Baseline with the authors' strict prompt                              |
| `baseline_labeldef_val`      | label-definition ablation (`experiments/label_definition/`)           |
| `dual_agent_val_greedyval`   | Dual-Agent with a greedy Validator                                    |
| `dual_agent_val_strictdet`   | Dual-Agent with the strict prompt for the Detector                    |
| `gan_val_greedy`             | GAN snapshots evaluated with greedy decoding                          |
| `gan_val_greedy_date`        | as `gan_val_greedy`, with a different chat date                       |
| `gan_val_phaseb_only`        | GAN ablation with Phase B only                                        |
| `sft_val_chat`               | SFT trained and evaluated in chat format                              |

`metrics/ch8_diagnostics.json` compares several of these runs with their
reference runs (chapter 8).

The controls named in Section 6.3 of the thesis:

| Control                       | Run(s)                                                   | Reference                  |
|-------------------------------|----------------------------------------------------------|----------------------------|
| chat-template date            | `baseline_val_date`, `gan_val_greedy_date`               | `baseline_val`, `gan_val_greedy` |
| stricter prompt of the authors| `baseline_val_strict`, `dual_agent_val_strictdet`        | `baseline_val`, `dual_agent_val` |
| RAG with random chunks        | `rag_val_random_dec06` (`rag_val_random`)                | `rag_val`                  |
| RAG without retrieved chunks  | `rag_val_nocontext_dec06` (`rag_val_nocontext`)          | `rag_val`                  |
| greedy Validator              | `dual_agent_val_greedyval`                               | `dual_agent_val`           |

## Strategy memories (Appendix A.2)

The final strategy memories S_G and S_D of every loop are in
`gan_val/seed<N>/snapshots/final.json` and `triple_agent_val/seed<N>/snapshots/final.json`
(the other snapshot files hold the memories after rounds 0, 10, 50 and 200).

## experiments.csv

Every official run appends one row. Some runs were repeated (dataset build,
SFT training seed 42, RAG seed 42); for each approach and seed the **last** row
belongs to the artefacts in this directory.

## Notes

- The comments in `configs/*.yaml` were shortened after the runs. The settings
  are unchanged, but `config_sha256` in the manifests refers to the file version
  with the old comments.
- The configuration of `rag_val_nocontext_dec06` was reconstructed from its
  manifest (`configs/rag_val_nocontext_dec06.yaml`).
- The logs and some manifests contain paths of the GPU server (the user name is replaced by `<user>`).
